# SaveSnapshot — 设计文档

> MC 世界快照 mod：保存 / 读取**内存中的世界状态快照**（不是完整世界文件）。
> 本文档由 grill-me 访谈结论整理，是后续开发的唯一依据。

## 2. 核心概念

### 2.1 快照内容（拍快照时捕捉什么）

快照 = **当前整合端内存中的世界状态**，明确**不是**磁盘上的完整世界：

- **所有维度**当前已加载的区块（不只玩家所在维度），包括：
  - 方块数据
  - 方块实体（箱子、熔炉等）
  - 实体（怪物、动物、掉落物等）
- **玩家状态**：位置、背包、装备、末影箱、血量、饥饿、经验等级、药水效果、骑乘状态
  - **例外**：成就、配方书、统计数据**不回滚**（避免丢进度）
- **维度全局状态**：世界时间、天气等

### 2.2 快照不捕捉什么

- 未加载的区块（磁盘上有但内存中没有的）
- 成就 / 配方 / 统计
- 游戏规则（gamerule）等 level.dat 全局设置——保持现状

### 2.3 恢复语义

- 采用**重进世界**方案：读档时把快照写回存档目录，自动退出到标题界面并重新进入世界，走原版加载流程。稳定可靠，代价是几秒加载黑屏。
- **快照范围外的区块不受影响**：读档只覆盖快照中包含的区块位置，玩家在拍快照后探索出的新区域保持现状。
- 读档前弹**确认框**（"当前进度将丢失"），不做自动备份。

## 3. 功能需求

### 3.1 手动快照
- 通过快照界面点击"新建快照"创建。
- 创建时**强制弹输入框手动命名**；需校验：非空、不含非法文件名字符、不与现有快照重名（重名提示覆盖或改名）。

### 3.2 自动快照
- 默认每 **10 分钟**自动拍一张（可在设置中开关、改间隔）。
- 最多保留 **10 张**自动快照，超出删最旧（轮转）。
- 自动快照命名 `auto-<时间戳>`，与手动快照分开计数，手动快照无数量限制。

### 3.3 快照列表界面
- 显示：名称、创建时间、（自动/手动）类型、大致大小。
- 操作：读取（带确认框）、重命名、删除。

### 3.4 入口
- **Mod Menu**：实现 `ModMenuApi.getModConfigScreenFactory()`，配置按钮打开快照界面；`fabric.mod.json` 注册 `modmenu` entrypoint。
- **按键**：注册 keybind（默认 F9），游戏内随时打开同一界面。

## 4. 存储设计

- 位置：世界存档目录下 `<world>/snapshots/<快照名>/`
- 格式：**原版 NBT**（`ChunkSerializer` 序列化区块），恢复时写回 region 文件后走原版加载。
  - 不用自定义二进制（调试难、版本升级维护成本高），不打 zip（读写多一步）。
- 目录结构（草案）：
  ```
  <world>/snapshots/<name>/
    meta.json            # 名称、创建时间、类型(manual/auto)、游戏版本
    regions/
      overworld/*.mca    # 只含快照覆盖的区块
      the_nether/*.mca
      ...
    player.dat           # 玩家 NBT
  ```

## 5. 模块划分（初步）

| 模块 | 职责 |
|---|---|
| `SnapshotManager` | 服务端（整合端）核心：创建/读取/删除/重命名/轮转 |
| `SnapshotCapture` | 遍历各维度已加载区块 → NBT；收集玩家 NBT、维度状态 |
| `SnapshotRestore` | 校验 → 写回存档 → 触发退出并重进世界 |
| `ui/SnapshotListScreen` | 自绘界面：列表、命名弹窗、确认弹窗、设置页 |
| `SaveSnapshotConfig` | JSON 配置：自动快照开关/间隔/上限、按键可见性 |
| `AutoSnapshotTicker` | 服务端 tick 计时，到点触发自动快照 |
| `SaveSnapshotModMenu` | `ModMenuApi` 实现 |

## 6. 边界情况与风险

- **一致性**：快照捕捉必须在主线程同一 tick 内完成，避免捕捉到半个 tick 的中间状态；磁盘写出可异步。
- **mod 兼容性**：快照含 mod 方块/实体时，读档环境需装有相同 mod，否则原版加载会丢弃未知内容（可接受，文档注明）。
- **游戏版本不一致**：meta.json 记录游戏版本，跨版本读档弹警告但不强制阻止。
- **磁盘空间**：写快照前估算可用空间，不足时提示并中止。
- **性能**：已加载区块量大时序列化可能卡顿；必要时分批 + 进度提示（列为后续优化项，首版不做）。

## 7. 里程碑

1. **M1 工程搭建**：fabric-example-mod 模板，MC 26.2 + Fabric API + Mod Menu 编译通过，游戏内可见 mod。
2. **M2 快照核心**：`SnapshotCapture` + `SnapshotRestore`，命令行触发（临时）验证保存/读档正确。
3. **M3 界面**：自绘快照列表屏 + 命名/确认弹窗，接入 Mod Menu 与 F9 按键。
4. **M4 自动快照**：计时器、轮转、JSON 配置与设置页。
5. **M5 收尾**：本地化（en_us/zh_cn）、mod 图标、边界情况处理、发布打包。
